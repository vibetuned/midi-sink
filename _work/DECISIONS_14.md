#### #1 — Step 87: the sustain pedal v2 — the half-pedal, re-pedalling, the pedal noises, the CC filter and the choke groups (2026-10-25; Voxo 0.27.0, the ABI unchanged; evidence `docs/evidence/step87`)

**What the spec asked** (`_work/ROADMAP_6.md` step 87; `TO_PROJECT_SPEC` §12.7): four mechanisms the format expects — (1) pedal noise and release-sample triggers, "`<group trigger="cc">` with `onLoCC`/`onHiCC`, evaluated on CC 64 crossing 64 upward or downward"; (2) half-pedalling, a note released at 0 < CC 64 < 127 entering a damped-sustain release whose rate interpolates between the preset's release and `sustainDecay`; (3) re-pedalling, the pedal pressed after note-off catching an audible tail at its level and slowing its decay; (4) choke groups — `silencedByTags` with `silencingMode` normal / fast — and "group-level `seqMode` gated by CC 64". The gates: a headless bounce of pedal-down, half-pedal, re-pedal and a hi-hat choke, each asserted on its envelope; zero audio-thread allocations; the compat report's sentences for these features retired. **What shipped is §12.7 as corrected below.** The decisions:

1. **The format's attributes, read from the format, not from the proposal (2026-10-25).** The Decent Sampler developer guide (`decentsampler-developers-guide.readthedocs.io`, the `<groups>` element) was fetched before the parser was written. There is NO `trigger="cc"` — `trigger` takes attack, release, first, legato, continuous. A CC-triggered sample is written with the CC NUMBER IN THE ATTRIBUTE NAME: `onLoCC64="64" onHiCC64="127"` on the `<sample>` (or the group; "if you use onLoCCN, you must also use a corresponding onHiCCN for the same CC number"), the pedal-noise idiom being `<group name="Pedal Noise" pitchKeyTrack="0"><sample path="…DW.wav" onLoCC64="64" onHiCC64="127"/><sample path="…UP.wav" onLoCC64="0" onHiCC64="63"/></group>` (the maker's own answer in the Q&A thread "Sustain Pedal Noise", 2021: no rootNote, loNote or hiNote on such samples). The note-on filter is `loCCN`/`hiCCN` ("when a note-on is received the engine decides, from the last received value of that CC, whether the sample plays"). The choke is `silencedByTags`, `silencingMode` fast | normal — THE DEFAULT IS FAST ("immediately") — and `silencingDecay` (seconds, overriding the mode). `sustainDecay` appears nowhere: it is VOXO'S OWN attribute, kept under the proposal's name (the format ignores what it does not know). The proposal's "group-level `seqMode` gated by CC 64" has no attribute behind it; the pedal-down and pedal-up groups the author meant are `loCC64`/`hiCC64` on the groups, which is what ships.
2. **What the parser reads** (`voxo/src/ds_preset.cpp`, `ds_preset.h`): `cc_range` finds the first `onLoCC<N>` / `loCC<N>` attribute on the sample, the group or `<groups>` (the cascade), composes the `hi` partner's name from N and reads it through the same cascade (hi < lo swapped; a missing hi = 127; N 0..127, three digits at most); `silencedByTags`, `silencingMode`, `silencingDecay`, `pitchKeyTrack` and `sustainDecay` cascade the same way; a sample's `tags` ADD to its group's. `trigger="continuous"` is parsed and plays as an attack zone (the always-on sample is not built — recorded). One CC pair of each kind per element: the first found.
3. **The compiled zone and the dictionary** (`instrument.h/.cpp`): a zone carries `on_cc` / `on_lo` / `on_hi` (255 = a note zone), `cond_cc` / `cond_lo` / `cond_hi` (255 = unconditional), `key_track`, `tag_mask` and `silenced_by` — the instrument's tag DICTIONARY gives every distinct tag a bit, 64 at most (a 65th tag neither silences nor is silenced; a library with more is beyond the format's drum kits) — and `silence_s`: silencingDecay as given, else 5 ms for fast (the engine's release floor: "immediately" clicks), −1 for normal (the group's release). The instrument lists its CC-triggered zones (`cc_zones`) and the CCs they watch (`cc_trigger_mask`), and flags `choke` when any zone is silenced by anything, so the dispatch pays for the pass only in presets that use it. A CC-triggered zone ANSWERS NO NOTE (it leaves the reach mask too): the Q&A's samples carry no note range, and the format's defaults would otherwise fire a thump on every key.
4. **THE PEDAL IS A POSITION, THE RATES INTERPOLATE** (`voxo.cpp`: `Channel::pedal`, `pedal_damp_coef`, `pedal_set`, `pedal_apply`). CC 64 / 127 is the pedal's position p on the channel (the master's reaches the zone, as before). A note-off at p > 0 is held (`pedalled`), and every note layer takes a second envelope factor, `damp`, decaying toward silence at the rate r(p) = (1 − p)·r_release + p·r_down — r_release = 4.6 / the group's release (5 ms at least), r_down = 4.6 / `sustainDecay`, or 0 without it. So: a switch pedal at 127 on a preset without the attribute gives r = 0 — the hold, BIT FOR BIT the old pedal (damp stays 1.0: x + (−x·0) and gg·1.0 are exact; the two pedal gates of `voxo_tests` and the MPE-zone gate pass unchanged); a preset that declares `sustainDecay="1.0"` decays under the full pedal at 4.6 / s (measured: the ratio across a quarter second 0.317, the formula's 0.317); a continuous pedal half way (64) on the same preset decays at 25.1 / s (measured 0.081 over a tenth of a second, the formula's 0.081). The pedal moving re-damps every pedalled voice (lifting slowly speeds the decay progressively); p = 0 releases what it held, the release samples firing as before. Known and accepted: a switch pedal that sends 64 for "down" (rare; most send 127) now holds a note at half the release rate instead of forever on presets without `sustainDecay`; the option of a threshold waits for a library that shows it. A Suzu voice under the pedal takes the same rule through its declared contraction (its T60 stretched by 1/(1 − p); the full pedal a hold, as before); the sine holds.
5. **RE-PEDALLING CATCHES A TAIL WHERE IT IS** (`pedal_apply`, `ENV_HOLD`). The pedal coming down (p > 0) over a voice that is releasing with a note layer still audible (env × damp > 10⁻³, not a release sample, not a choked layer) moves that layer to ENV_HOLD — the envelope frozen at its value — and the voice back to `pedalled`; its decay from there is the pedal's damping, its next lift the normal release. No attack, no jump: the layer's output continues from the same sample. Measured: a note lifted and caught 30 ms into its 0.1 s release sits at 0.0356 (0.5 × UNIT × e^{−1.38}) and reads 0.0356 half a second later; the lift empties it in the release. A pedal noise, a choked layer and a release sample are never caught; the CC-triggered voices are never pedalled.
6. **THE PEDAL NOISES FIRE ONCE PER CROSSING** (`cc_fire`, `Voice::cc_voice`). Every CC's last value is kept per channel (`Channel::cc_last[128]`, the master's written to the zone); a zone with `onLoCCN`/`onHiCCN` fires when CC N's value ENTERS its range — the previous value outside, the new one inside — as a voice of its own on the event's channel: no note (`note` 0xFF, so no note-off finds it), full velocity, the pitch of the zone's root through `pitchKeyTrack` (0 the root exactly: `freq` raised to the tracking's power, 1 bit for bit the note), never held, never pedalled, its layers playing out through the group's envelope to the sample's end; its tags choke what they choke. The format, by the maker's note on a Pianobook piano, triggers on EVERY message inside the range ("the PEDALDOWN.wav will be triggered repeatedly while holding the pedal down") — Voxo fires on the crossing, the proposal's reading, so a continuous pedal does not machine-gun the thump; recorded as a deliberate difference. Measured: the pedal going to 127 fires the 0.25 zone once (one voice, one layer; 127 and 100 again add nothing; it ends), to 0 the 0.125 zone once (30 again adds nothing). The CC filter: note 60's resonance zone, `loCC64="64" hiCC64="127"`, silent with the pedal up, playing with it down — the pedal-down resonance group of the proposal, through the format's own mechanism.
7. **THE CHOKE RUNS BEFORE THE NEW LAYERS START** (`choke_layers`). A dispatch (a note-on, a release trigger, a CC trigger) first ORs the tag masks of the zones about to start and silences every playing layer anywhere whose `silenced_by` meets them — so a group silenced by its own tag (a mono hi-hat) chokes its predecessor and never itself — then starts the new layers. A choked layer goes to its release phase with its coefficient from `silence_s` (5 ms, silencingDecay's, or the group's release) and is marked, so a later note-off changes nothing and a re-pedal does not catch it. Measured on two open hats (looped 0.5) and a closed hat (looped 0.25): both opens 1.0 × UNIT; 20 ms after the closed hat strikes 0.1789 against the formula's 0.1788 (the fast one gone within its 5 ms, the normal one at e^{−4.6·0.0175/0.3} of its level in its 0.3 s release); after it the closed hat alone, one layer. The union over a round robin's candidates (one tag set for every position) can over-silence by a tag only some positions carry — a kit that does that is not known; recorded.
8. **The contract and the fuzz.** Nothing above allocates in the callback: the CC voices come from the pool, the tag dictionary and the CC-zone list are compiled on the shell thread, the per-channel CC memory is 2 KB of plain bytes. The preset suite's blocks 19 and 20 arm the counting allocator around the pedal noises, the filter, the catch and the choke (the suite's own measurement buffer allocated before arming — the first run counted its own `std::vector`s, eleven and three, and was corrected). `voxo_fuzz` seeds the two pedal fixtures and their samples and, after every load that succeeds, plays five notes through a random pedal position, a lift, a catch and a panic, asserting finite output: 280 271 loads in 60 s, 108 776 loaded, no crash, no non-finite sample.
9. **The compat report retires no sentence**, because none covered these features: a pedal-noise sample was silently a note zone and a choke tag was ignored — the report had no line for an attribute. `voxo/COMPAT_REPORT.md` gains a paragraph on what the pedal mechanics play since this step; the eleven canonical sentences stand and the test that pins them passes.
10. **Found in the web gate: step 86's matrix section was never bit for bit, and its record did not show it.** The gate read RED on the Duffing's matrix section — the audio bit-identical, the trace, the inspection and the recent trace within −100.9 dB from the section's slide event on. Not the pedal (no CC 64 in the script) and not the chaotic modulator (the section without it reads the same): the slide-to-pitch route of step 86 multiplies the frequency by `exp2f(m/12)`, an ulp apart between the libraries, and the cell's state walks from there (the plain Duffing section stays bit for bit). The class is the TOLERANT list's (the trumpet's pow, the sax's exp2f); kind 4 joins it with the measured figure, the gate GREEN again. Step 86's evidence file (`web_and_lab_gates.txt`) held the gate's tail only, so the line never appeared: an evidence file is the whole output, never a tail — the rule from here.
11. **The tablets, both plugged in, and the spike's pedal.** The shells' spike storms (`ios/Sources/VoxoSpike.swift`, `android/cpp/sumi_jni.cpp`: a test hook, not a feature) now press the pedal on the master channel across their forty pushed notes — down for ten (their note-offs held, the damping), half way for five, up for five (the catch on the next press) — so a device run exercises the pedal's paths under the storm. On the sampler's Dan Tranh demo both are clean: the iPad 0 XRuns, render at most 0.105 ms of its 2.67 ms burst; the Tab (the release APK signed with the debug key) 0 XRuns, 0.801 ms of its 4 ms. On Suzu patch 0 the iPad reads 0.210 ms and the Tab 21 proxy XRuns at 4.424 ms — the carried Tab item of `DECISIONS_13 #1` (its audio thread some forty times the Mac's cost; a shell thread-placement item, ADPF/affinity), now with the pedal holding fifteen voices under the storm; AAudio reports 0 device XRuns on both runs. Not this step's code: the sampler's run is the one the pedal touches, and it is clean.
12. **What stays with the proposal and what does not.** Kept: the four mechanisms, the rate interpolation, the catch, `sustainDecay`'s name and meaning, the gates. Corrected: the attribute names (above), the choke's default (fast, the format's), "a 5 ms linear fade" is a 5 ms one-pole (the engine's release floor, no click), the "seqMode gated by CC 64" (it is `loCC64`/`hiCC64`). Not built, recorded: `trigger="continuous"`, `previousNotes` / `legatoInterval` (step 90's legato), `releaseTriggerDecay`, tag polyphony limits, a `cc` voice's velocity from the CC's value (full velocity ships), more than one CC pair per element, the switch-pedal-at-64 threshold.

**Evidence** (`docs/evidence/step87/SUMMARY.md`): the Release suites (the preset suite's blocks 16–20, the sampler suite, the synth suite), the Debug ctest, the fuzz minute, the storm on the Dan Tranh library, the web and lab gates, both tablets under the spike with the pedal (`tablets.txt`, `tablets/`).

#### #2 — Step 88: the chorus and the phaser, and the CC map's chorus targets (2026-10-25; Voxo 0.28.0, additive — `VOXO_CTL_CHORUS_MIX` / `_RATE` / `_DEPTH`; evidence `docs/evidence/step88`)

**What the spec asked** (`_work/ROADMAP_6.md` step 88; `TO_PROJECT_SPEC` §12.8): `<effect type="chorus">` at bus and group level — a stereo quadrature-LFO delay line pre-allocated at load (mix, modDepth, modRate, the 90° stereo offset), 4-point Hermite reads; `<effect type="phaser">` — 4 or 6 cascaded all-passes under a stereo LFO (mix, modDepth, modRate, feedback, centerFrequency); the CC map's 1006–1008. The gates: the effects bit-identical across the native builds at a fixed seed; the storm with chorus on every voice at 0 XRuns; the report's chorus sentence retired. **What shipped is §12.8's chorus and phaser as corrected** (the EQ, the gain and the wave shaper of the same subsection are step 89's by the roadmap). The decisions:

1. **The format, read first** (the developer guide's `<effects>` element and Appendix B). The chorus takes `mix` (0..1, default 0.5), `modDepth` (0..1, 0.2), `modRate` (Hz, 0..10, 0.2) and nothing else — no delay, feedback or width attribute. The phaser takes those plus `centerFrequency` (Hz, 0..22000, 400) and `feedback` (−1..1, 0.7); it has no `stages` attribute (six it is, the proposal's "4 or 6" decided by the format's silence). Group-level effects are PER VOICE in the format ("initialized every time a note is started … two notes, two instances"), and only the filters, the gain and the chorus may sit at the group level — the phaser is the bus's alone. Every effect takes `enabled` (default true). The generic binding names — `FX_MIX`, `FX_MOD_DEPTH`, `FX_MOD_RATE`, `FX_CENTER_FREQUENCY`, `FX_FEEDBACK` (from the appendix's summary, the page's verbatim half ending before the effect rows) — name the effect by its position, so the parser resolves them by the KIND of the effect the binding points at (`binding_kind`: the instrument's by `position`, a group's by `effectIndex`); the unambiguous names stay as they were.
2. **The chorus** (`bus.h/.cpp` `Chorus`): two delay lines at a 7 ms centre swung by ±4 ms × depth (`CENTRE_MS`, `SWING_MS` — `[ITERATE]` by ear against the author's chorus library), the LFO a magic-circle cell — the leapfrog rotation of `suzu.h`, exact and drift-free, its (x, y) the quadrature pair, so the right channel is 90° from the left for free and the prewarp `2 sin(π f/fs)` is the one libm call, once a block — the fractional read the §12.2 Hermite (`hermite4`, the same tangents as the sampler's), the output (1 − mix)·dry + mix·wet with mix 0 leaving the samples untouched. THE BUFFERS ARE FIXED (1536 frames a channel, 16 ms at 96 kHz; the swing never exceeds 11 ms), so an instance sits inside every `Voice` (12 KB, 786 KB over the pool of 64) and one on the bus: no allocation anywhere, the "pre-allocated at load" of the proposal made structural. The group-level chorus follows the format: a chorused voice's layers are summed into a scratch block (`voice_scratch`, 4096 frames; a larger block skips the group chorus, as the plate's does), its own chorus runs on the sum, the result is added to the bus — one instance a note, the settings of the first group carrying a layer when a stack spans groups (recorded), the live values from the group's state (its `FX_MIX` / `FX_MOD_DEPTH` / `FX_MOD_RATE` bindings). A fresh note clears its chorus (the fixed seed: the LFO at phase 0); a retrigger keeps its line.
3. **The phaser** (`Phaser`): six first-order all-pass stages a channel, H = (a + z⁻¹)/(1 + a z⁻¹) with a = (tan(πf/fs) − 1)/(tan(πf/fs) + 1), swept f = centerFrequency × 2^(2·depth·lfo) — ±2 octaves at full depth, the coefficient refreshed every sixteen samples (a tan a channel, a staircase 60 dB under the sweep) — the feedback from the chain's last output into its input, held within ±0.95 (the format's ±1 is the loop's margin), the output (1 − mix)·dry + mix·chain. Mix 0 returns before touching the block. At the centre the chain's phase is −3π exactly, so mix ½ is a true notch there: the saw's 440 Hz harmonic 132 dB down with the phaser frozen at 440 (gate 24), 220 Hz within 0.6 dB (the chain's −318.8° there), and at mix 1 the chain alone passes every harmonic at the dry's level.
4. **Bit-identical across the native builds.** The chorus and the phaser are compiled without fused multiply-add contraction (`bus.cpp`'s `#pragma clang fp contract(off)` / GCC's `optimize` / MSVC's `fp_contract`, placed before them so the reverb and the delay keep the compiler's default), and their only libm calls are the prewarp's `sin` and the phaser's `tan` / `exp2` — the same bits in the Debug (-O0 still contracts: the frontend's fmuladd intrinsic lowers to fmadd on arm64 whatever the level, found below), the Release and the no-FMA reference builds on one platform. Measured: two fresh instances of the sweep identical in every sample, the output's FNV hash `66a88a01` in the Debug run — the Release run's hash is in the evidence beside it.
5. **Found: the Debug build fuses too.** The group-chorus gate first asked for two chorused notes to equal the dry pair delayed, bit for bit; they sat a last bit apart in a third of the samples. Not the chorus (one note is bit for bit against the dry delayed, through the bus and through the group): the dry path accumulates each layer with `out += s·g·pan`, which clang contracts into one fused rounding even at -O0, while the chorused path rounds the product into the scratch and adds afterwards. The gate is a tolerance now (−143.6 dB of the peak measured, the bar −120) and the class is recorded: the sampler's own mix is FMA-dependent wherever two voices add, which is why the chorus and the phaser carry the pragma and the sampler does not.
6. **The gates** (`tests/voxo_preset_tests.cpp` 21–25 on `tests/fixtures/dspresets/fx/`: a 220 Hz sine and a 110 Hz saw looped on whole periods). 21: the bus chorus at mix 0 is the dry bit for bit; mix 1 at depth 0 through `VOXO_CTL_CHORUS_MIX` is the dry delayed by exactly 336 samples at 48 k (7 ms), bit for bit, the first 336 samples silent. 22: full depth at 2 Hz through `VOXO_CTL_CHORUS_DEPTH`: the left's pitch swings 209.2–231.0 Hz, 21.8 Hz peak to peak against the formula's 22.1 (±4 ms × 2π × 2 Hz on 220 Hz); where the left's swing peaks (+11.0 Hz) the right reads −0.8 Hz — the quadrature. 23: the group chorus on one note is the bus chorus bit for bit; two notes the dry pair delayed within −143.6 dB; nothing allocated. 24: the phaser's notch (above) and its `FX_MIX` binding resolved by position. 25: the sweep with feedback 0.7 bounded (peak 0.368 against the dry's 0.258), finite, two fresh instances identical, the 440 Hz harmonic moving 20.4 dB across 50 ms windows of the period (a quarter-second window averaged the sweep away: 0.4 dB — the window follows the notch's dwell); a disabled chorus beside it passed over. The fuzz seeds the three effects presets and their waves: 256 925 loads in 60 s, 100 383 loaded, no crash.
7. **The CC map and the shells.** `VOXO_CTL_CHORUS_MIX` 1006 (0..1), `_RATE` 1007 (0..10 Hz: the CC × 10), `_DEPTH` 1008 (0..1), `VOXO_CTL_COUNT` 9; a route turns the bus chorus on, as the reverb's do. `presets/SCHEMA.md` names them; the desktop's target table (`app_ctl_target_count` + 9, the names), the iPad's reload range (1000…1008) and the Tab's name list carry them; the settings reference lists the three. The report's chorus sentence is retired — `VOXO_NOTE_CHORUS` stays in the ABI, never raised, its copy empty — and the phaser no longer appears among the unknown effects; `features.dspreset` gained a `bit_crusher` so the unknown-effect note keeps a witness; the copy test skips a retired bit.
8. **Not built, recorded:** the bus EQ, `<effect type="gain">` as a bus stage and `<effect type="wave_shaper">` (step 89); the listed order of the bus effects (chorus, phaser, reverb, delay is Voxo's); a stack spanning groups with different choruses (the first group's rules); `stereo_simulator`, `pitch_shift`, `wave_folder`, `bit_crusher`, `compressor`, `stutter` (the unknown effects, named in the report); `effectTags` on a binding; the phaser's `stages` (none in the format).

**Evidence** (`docs/evidence/step88/SUMMARY.md`): the Release suites, the Debug ctest, the fuzz minute, the storm on the Dan Tranh library with a chorus on every voice and the phaser on the bus, the web and lab gates, the tablets' compiles.

#### #3 — Step 89: the filter family, the filter envelope, the bus EQ, the gain and the wave shaper (2026-10-25; Voxo 0.29.0, no new entry point; evidence `docs/evidence/step89`)

**What the spec asked** (`_work/ROADMAP_6.md` step 89; `TO_PROJECT_SPEC` §12.9 and the tail of §12.8): the per-voice SVF's highpass, bandpass, notch, peak and lowpass_1pl outputs from the same loop; `<modulators><envelope>` to cutoff and resonance; `<effect type="eq">` (low shelf, peaking mid, high shelf), `<effect type="gain">`, `<effect type="wave_shaper">`. The gates: each filter's response against its analytic curve within 0.5 dB; the report's "other filters" sentence retired. **What shipped is §12.9 as corrected** (the subsection rewritten as shipped). The decisions:

1. **The format, read first** (the developer guide's `<effects>` element and the modulators page). The voice filters are `lowpass` (`lowpass_4pl` the legacy spelling), `lowpass_1pl` (no resonance), `bandpass`, `highpass`, all with `frequency` and `resonance` — and **`resonance` is the Q** (0.001..5, default 0.7), not an amount: step 51 read it as `clamp(resonance − 0.7, 0, 1)` and mapped that to k = 2 − 1.9·amount, so a preset at the default sat at Q 0.5 (−6 dB at the cutoff) instead of 0.7 (−3 dB). Corrected: k = 1/Q, Q held within 0.1..18 (`Group::resonance`, `GroupState::resonance` and the `FX_FILTER_RESONANCE` / `FX_FILTER_Q` bindings carry the Q itself); every lowpass preset is 3 dB brighter at its cutoff than at 2.0, and the step-51 CC 74 gate's margin shrank from a factor 2 to 1.49 between the open and the centre readings (the bar lowered to 1.3, the ordering intact). `notch` takes `Q`/`q` (0.01..18, 0.7) at 10 kHz by default; `peak` adds `gain` (linear 0.0001..10, or decibels under `gainUnit="decibels"`) — there is **no `<effect type="eq">`**: the EQ is `peak`, `low_shelf` (200 Hz) and `high_shelf` (5 kHz) with `q`, `gain`, `gainUnit`. `gain` takes `level` in dB by default (`"-6dB"` allowed; the default −6 dB) or linear under `levelUnit="linear"`. `wave_shaper` takes `drive` (1..1000), `driveBoost` (0..1), `outputLevel` (0..1, default 0.1) and `highQuality` (read, ignored). The group level admits the filters, the gain, the chorus and (in the guide's examples) the wave shaper; the peak, the shelves and the notch are the bus's. The bindings: `FX_FILTER_FREQUENCY`, `FX_FILTER_Q`, `FX_FILTER_GAIN`, `FX_DRIVE`, `FX_DRIVE_BOOST`, `FX_OUTPUT_LEVEL`; `<envelope>` carries `attack`, `decay`, `sustain`, `release`, `modAmount`, `scope`, `modBehavior` (set | add | multiply | modulate).
2. **The family on the one SVF** (`voxo.cpp` `render_layer`, `Group::filter_mode`): the Zavalishin loop's low (v₂), high (v₀ − k·v₁ − v₂), band at unity (k·v₁) and notch (v₀ − k·v₁) outputs selected by the mode, the state and the per-sample coefficient ramp untouched; `lowpass_1pl` the TPT one-pole on the same state. The voice's filter is the group's first enabled lowpass / lowpass_1pl / highpass / bandpass / notch, else the instrument's first enabled lowpass / highpass / bandpass (an instrument-level notch is the bus EQ's, where the format puts it); none = a lowpass at 22 kHz so CC 74 moves something, as before. A lowpass at the top with the default Q skips the loop — the dry, bit for bit (the step-88 gates unchanged); the other modes always run. The proposal's "peak" output is not an SVF output: the peaking EQ is a biquad on the bus (below). Measured (gate 26, the Release run): every mode at 1 kHz at Q 0.7 and 2, and the one-pole, within 0.001 dB of its analytic curve over the saw's thirty harmonics — the TPT SVF is the exact bilinear transform of the analog prototype prewarped at the cutoff, |H(f)| the prototype's at Ω = tan(πf/fs)/tan(πfc/fs) — against the 0.5 dB bar; `lowpass_4pl` at the instrument level is the group's lowpass bit for bit; `enabled="false"` the dry bit for bit; the lowpass at Q 0.7 reads −3.01 dB on 990 Hz.
3. **The filter envelope** (`Layer::fenv` / `fenv_stage`, `fenv_advance`, `fenv_apply`): the first `<envelope>` carrying a binding on the voice filter's frequency or Q (instrument level: every group; group level: that group; one a group, the first wins) plays PER VOICE whatever its `scope` ("most envelopes should be per note" — the guide), stepped ONCE A BLOCK: a linear attack, an exponential decay (4.6/T) to the sustain, an exponential release that follows the amplitude envelope's (a note-off, a choke, a retrigger; the pedal's catch freezes it with the amplitude). Its value at the block's start and end is folded into the two cutoff coefficients that already ramp per sample, so the sweep costs the block's two tangents and nothing per sample; the Q is read at the block's start. `modAmount` scales the envelope before the binding's translation; `modBehavior` (the binding's, else the element's; default set): set replaces the cutoff — under the default timbre's multiplier, so CC 74 still plays — add adds, multiply scales, `modulate` is read as multiply (its definition is not on the page; recorded).
