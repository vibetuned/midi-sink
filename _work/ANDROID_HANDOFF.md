## Ground rules (unchanged, load-bearing)

* The core (`core/`) is FROZEN — everything you need is in the shipped ABI
  (v0.4.0: probe, wake, pinch, vortex profile, params
  slide/bend/press/pinch_variant/ripple). If you feel a core urge, log a
  flagged question in DECISIONS_3, don't code it.
* `hostmpe/` is the SHARED host library — allocator, joystick, limiters,
  strip, pen legato. Kotlin consumes it via JNI exactly as Swift does via
  the module map. **Never reimplement its math in Kotlin** — that drift is
  what the library exists to prevent. Its headless suite (1,559 checks) must
  run and pass in your build.
* §5.2 / DECISIONS_2 #33: `sumi_push_midi` has ONE producer thread on
  Android — the AMidi poller thread. ALL hostmpe state and every
  touch-generated byte must be marshalled onto it (the iOS equivalent is the
  serial `midiQueue`). The layout probe is instance-free precisely so
  hit-testing can run on the UI thread without touching that contract (#2).
* The user makes all commits. Prepare evidence under
  `docs/evidence/<task>/`, report readiness.
* Build: root CMake via Gradle (`android/` externalNativeBuild). Verify the
  §4.6 fixture: the GLES3 field dump must match
  `tests/fixtures/field_512_metal.bin` bitwise (the harness comparator).

   limiters (one per transport), strip engine, pen engine. All calls on the
   single-producer thread.
2. **Play mode + overlay (Compose)** — mode toggle per PHASE4 §1 (playable:
   CHROMA_GRID, JANKO, PIANO_GRID); lattice = a probe SWEEP, never
   Kotlin-side geometry (#9); **two-tone rings** (paper-cream halo under the
   dark stroke, ACCIDENTAL rings drawn last/on top — #41); per-touch
   joystick indicator (R_max circle + Δ_eff thumb via `hostmpe_joystick_eff`);
   saturation = HUD blink, never steal. Entering Play mode pushes
   MCM/RPN0 into the loopback FIRST (working rule).
3. **Fingers** — hostmpe joystick verbatim: X bend
   (semitone-exact, #10 identity-beyond-knee, #16 floor), **bipolar Y**
   (up = 0xD0 feed, down = 0xA0 swirl on the voice's note — PHASE4 §3.3,
   #37), synthesized velocity 96 (touch-size modulation behind a setting),
   no CC74 from fingers, ever.
4. **Transports** — USB gadget MIDI is the PRIMARY sink (status surfaced:
   active/charge-only/unsupported; watch USB mode flips), MidiDeviceService
   virtual device, BLE advertise. MCM/RPN0 + strip announce on every sink
   open AND on mid-session appearance; per-transport limiters (≤100 Hz
   rate class; BLE ~300 msg/s budget class); departing sink gets
   `hostmpe_silence_zone`; panic button = `hostmpe_panic` everywhere.
5. **Control strip** — compact FLOATING palette top-left over the
   full-canvas lattice (#31 — never a docked band: displacing the lattice
   broke drop-under-finger on device). Widgets from `hostmpe_strip_t`:
   Pitch spring (tick each frame), Mod latch, Sustain momentary (a
   long-press CC editor for the two assignables; protocol CCs are refused
   engine-side). Buttons ride exempt (never-dropped, #30); wheels are
   policed. Strip re-announces after every session-config send. Track every
   widget touch — a release resolves by grab record, and keep any
   long-press recognizer OFF the sustain pad (#31's cancel bug).
6. **S-Pen** (the Pencil's sibling — ALL final semantics, #38–#41):
   * Velocity: calibrate so a baseline tap = 96 and hard = 127 —
     `getPressure()` at ACTION_DOWN has the same builds-after-contact trap
     as UIKit force (#38 corrected); clamp sub-baseline UP to 96.
   * **Per-cell legato** via `hostmpe_pen_glide`: probe the cell under the
     pen each move; crossing = bend→On(live velocity)→old-Off on one
     channel; ±0.65 st boundary hysteresis is engine-side (#39). No re-anchor,
     no retune ramps — they were retired.
   * In-cell offset = the bend, baseline scale ×1 ALWAYS (#40 final — never
     gate it to zero); the booster multiplies ×1→×3 and decays (τ 0.4 s),
     re-emitting the fading scale each frame.
   * **Booster feed**: S-Pen has no barrel roll — use the azimuth tail-stir
     fallback (deltas only, posture-gated on tilt rate, tip-planted
     discriminator < 3 pt/event, per-event floor + spike clamps). If the
     hardware ever grows a roll axis, that becomes primary (#40).
   * **NO orientation→vortex of any kind** (#40 final: removed after
     repeated leaks; the mod belongs to the strip).
   * CC74 from knee-shaped Δy about the strike; with `slide_mode = 1` the
     shell drives `sumi_add_pinch` (fold axis from pen orientation) and CC74
     goes OUTBOUND ONLY (#38 — loopback too would double-pinch).
   * `sumi_add_wake` on every stroke segment (tip radius from pressure) —
     physical, never MIDI (the §7 invariant).
   * Hover ghost where the hardware reports hover (ACTION_HOVER_MOVE).
7. **Marble pinch** — two-finger pinch → `sumi_add_pinch`, fold axis = the
   finger-to-finger line (isotropic point space needs no aspect fix), k from
   scale DELTAS (#41).
8. **Note-off is silent** — the lift ring was removed (#41): a release stops
   the feed and stamps NOTHING. Do not port any surfactant-ring code.

## Lessons paid for on iOS (do not relearn)

* **Stale native libs**: the app links prebuilt static libs — after ANY
  core/hostmpe change, rebuild the native side BEFORE the app build, or you
  ship the old engine and chase ghosts (this cost us a session).
* **Batch integrity**: any pen/touch batch containing a Note On ships WHOLE
  as exempt/strike class on every transport — a legato crossing must arrive
  intact.
* **Orientation sensors lie**: tilt cross-talks into everything; absolute
  orientation values are unusable (noise + no zero). Deltas only, posture
  gates, decay-to-neutral. When in doubt, make it a gesture, not a knob.
* **Half-float ULP freeze** (#37): sub-quantum per-pass displacements near a
  vortex core round away — protective, but field measurements near r→0 read
  low; don't chase it as a bug.
* **The DONE gates for the Android step** are in ROADMAP_3's final step
  (USB-wired `amidi -l` + Linux DAW handshake, latency beats BLE, full
  hostmpe suite on-device, channel-steal re-run with the ROLI, 10-minute
  mixed session, zero stuck notes) — plus everything above behaving exactly
  as on iOS, because the engine is the same bytes.
