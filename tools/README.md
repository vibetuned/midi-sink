# tools/

Scripts that outlive the evidence folders they were written in (`docs/evidence/`
is removed from the tree when a phase ships; git history keeps it).

| Path | What it is | Where it came from |
|---|---|---|
| `chart_check.py` | Verifies `site/src/data/midi-chart.json` against the Play-mode byte logs in `tests/fixtures/bytelogs/` (`npm run chart` in `site/`, and the PR workflow). | Step 26 |
| `field_gate.py`, `web_gate.mjs`, `web_serve.py` | The §4.6 cross-backend field regression on the desktop renderers and on WebGPU (headless Chrome: field dump, scene sweep, page captures). | Steps 24–25 |
| `midi_asserts.py`, `pen_trace.py` | Byte-log analysers for the tablets' Play-mode streams (handshake order, rate policies, legato reconstruction). | Phase 4 |
| `release_notes.py` | The `## v<version>` section of `docs/CHANGELOG.md` as release notes (`--strict` on real tags). | Step 24 |
| `gen_icons.py` | Every platform's icon from `images/midi-sink.jpg` (`--only site` for the docs/web icons). Needs Pillow + numpy. | Step 14 / Phase 5 |
| `soak_report.py` | The `[soak]` lines of `midi-sink --dev --soak …` / `--soak-negative` logs as one Markdown table: per operator its class, the (b)/(c)/(d) numbers and verdicts, plus the negative controls' outcomes (`soak_report.py <log>… --out table.md`). | Step 35 |
| `voxo_spike/` | The tablets' touch-to-sound spike runners (Android over adb, iOS over devicectl) and the microphone onset check, from steps 48 and 54 (DECISIONS_6 #7–#9, #28). | Steps 48, 54 |
| `windows_wasapi/` | The Windows box's WASAPI helpers: switch the default render endpoint, list the endpoints' audio sessions — how hotplug and the engine period were verified (DECISIONS_6 #39, #41). | Step 55 |
| `fetch_dan_tranh.py` | The demo instrument (Phase 7 steps 52–53): downloads the VCSL Dan Tranh's "Normal" articulation (CC0) as a three-layer test library outside the tree, converted from its SFZ, and writes the bundled demo into `voxo/demo/` — the f layer at 32 kHz mono, trimmed and normalised, across the keyboard (needs ffmpeg). DECISIONS_6 #22. | Step 53 |
| `voxo_glide_check.py` | The glide's offline spectral check (Phase 7 step 49): frames the bounce `midi-sink --dev --voxo-bounce <dir>` wrote and reports the artefact-to-signal ratio per interpolation — Hermite at or under −55 dB, linear at least 10 dB behind (DECISIONS_6 #10). numpy through `uv run tools/voxo_glide_check.py --dir <dir>`. | Step 49 |
| `stokeslet_verify.py` | The 2-D unsteady Stokeslet displacement kernel derived and checked numerically (E₁ series, divergence, the d_y sign) — the viscous stroke's paper trail (DECISIONS_4 #53). | Step 33 |
| `sound_profile.py` | The SOUND PROFILE of a Voxo source (Phase 8 step 56, the author's ask): draws `midi-sink --dev --voxo-profile <dir>`'s run — every note 21..108 struck offline — as the level across the keyboard (peak, RMS), the first three harmonics per note and a spectrogram; `uv run`. One per synth in the evidence and the docs. | Step 56 |
| `chaos_chart.py` | The chaos charts (Phase 8 step 58, SYNTH §2.3, §2.10, §5): the kicked rotor's K sweep and the driven Duffing cell's drive sweep as spectrograms with the swept parameter on the top axis, and the Duffing clang as pitch against time — from `midi-sink --dev --voxo-chart <dir>`; from step 58b the flute's breath ramp too (the overblow, SYNTH §2.13), from 58c the sax's breath ramp and the trumpet's embouchure sweep (the registers, §2.12); `uv run`. | Step 58 |
| `mode_splitting_chart.py` | Mode splitting, charted once (Phase 8 step 57, SYNTH §2.5): two coupled cells' split against κ (measured beat vs the joint map's normal modes) and the pair's spectrum, from the CSVs `voxo_suzu_tests` writes with `SUZU_EVIDENCE=<dir>`; `uv run`. | Step 57 |
| `strike_compare.py` | The Tab-versus-Mac strike judgement (DECISIONS_5 #88, DECISIONS_7 #4): counts the lit charges of a six-strike print — a bench PNG or a raw w,h + RGBA8 dump — as connected components above the glass; `uv run`, needs numpy, pillow, scipy. | Step 55b |
| `composite_gate.py` | The composite screenshot regression as a gate: runs `midi-sink --dev --composite-dump`, compares the print of the canonical field script against `tests/fixtures/composite_512_metal.rgba` at the backend's tier (`--backend`: Metal bitwise, GL / D3D11 one 8-bit step — DECISIONS_5 #78, #83, #87), and proves red on a corrupted copy (Phase 6 step 41, DECISIONS_5 #48). | Step 41 |
| `multipole_verify.py` | The viscous multipole burst derived and checked numerically: the multipole heat kernel and its stream function, the time integral Φ_m (E₁ at m = 1, elementary for m ≥ 2, the spec's form), the divergence-free displacement, the strain limit, the far field, the lobe peak and the per-pass fold budget β_m (MEDIUM §2.3, DECISIONS_5 #28–#29). | Step 38 |
| `coremidi_recover.sh` | macOS: diagnoses and, with `--fix`, resets a wedged CoreMIDI setup store — MIDIServer crashing every few seconds in `CheckWritePrefFile` after too many instruments came and went, taking every client's inputs with it. Backs the setup files up, removes them, restarts MIDIServer and watches it survive the crash window. No sudo. | Phase 6 (author) |
| `linux/roli_capture.sh` | ROLI-over-ALSA byte capture while a human plays (`tools/linux/roli_capture.sh [seconds] [out.csv]`), with the byte summary and the informational `midi_asserts.py capture`. | Step 30 |
| `linux/aptlocal.sh` | End-to-end test of the apt repository shape `pages.yml` builds (formerly `publish-apt.yml`): throwaway key, the same `apt-ftparchive`/`gpg` commands, a clean container installing from it over http. | Step 30 |
| `linux/jammy_probe.sh` | Builds the tree inside an `ubuntu:22.04` container (Kitware CMake, gcc-12) — the glibc-floor probe for the Linux lane. | Step 30 |
| `linux_automation/` | The Step-33 desktop checks driven on X11 (XTest pointer/keyboard, MIDI files into the ALSA Through port, `import` captures — `x11auto.py` is the helper, `cases*.py` the cases, `mkmidi.py` writes the SMF files) and on Wayland through mutter's remote-desktop API (`mutterrd.py`, `wlcases_mutter.py`, `wlclick.py`). Set `MIDI_SINK_ROOT` if the tree is not two levels up. | Step 33 (Linux box) |
| `android_automation/` | The Step-33 Android checks over adb (`droid.py` is the uiautomator/`input` driver; `droid_final*.py`, `droid_rows.py`, `droid_replay_check.py` the check sets; JSON results beside the run). Set `MIDI_SINK_ROOT` for the APK path. | Step 33 (Linux box) |
| `store_screenshots/` | The v1.0.0 store-submission screenshot scripts (Simulator touch injection, adb composition, the 16:9 crop, the feature graphic) — see its README. | Store submission prep (after step 34) |

The desktop lab bench itself (`midi-sink --dev …`, the scripted operator tests)
lives in `desktop/src/dev_tools.cpp`; the headless suites in `tests/`.
