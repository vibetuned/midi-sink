## Codebase orientation (validated facts, found the hard way on macOS)

- **Build**: `cmake -B build -G Ninja && cmake --build build && ctest
  --test-dir build`. All dependencies (glm, sokol, libremidi, GLFW, stb,
  sokol-shdc prebuilt) are FetchContent/download-pinned in `CMakeLists.txt`
  and `cmake/CompileShaders.cmake` — the shdc helper already knows the win32
  binary name. `tests/normalizer_tests.cpp` (8,934 checks) and
  `tests/abi_c_compile.c` are GPU-free and must pass unchanged.
- **One y-down texture space (§4.6)**: every pass samples at
  `st = (u, 1 − v_clip)` emitted by the fullscreen-triangle VS
  (`core/src/shaders/deform.glsl`). Do NOT "fix" anything by flipping inside
  the deformation chain — on Metal that exact mistake made consecutive
  deformations cancel. D3D11 shares Metal's top-left origin, so the correct
  amount of new flip code for this step is expected to be **zero**.
- **SOKOL_IMPL hosting (DECISIONS #1)**: `swapchain_metal.mm` defines
  `SOKOL_IMPL` + `SOKOL_METAL` for the mac build. Mirror the pattern:
  `swapchain_d3d11.cpp` defines `SOKOL_IMPL` + `SOKOL_D3D11`, and is the only
  TU allowed to include d3d11/dxgi headers. `renderer.cpp` includes sokol
  declarations only. Guard against double-definition (include via
  `swapchain.h` exactly once).
- **Metal-specific seam you must generalize**: `renderer.cpp:173` calls
  `sg_mtl_query_image_info()` / `sg_mtl_command_queue()` to hand the print
  texture to `sumi_swapchain_readback_begin(sc, mtl_queue, mtl_texture, w, h)`
  (`core/src/swapchain.h`). Refactor this seam to a backend-neutral signature
  (e.g. pass the `sg_image` handle and let each swapchain TU do its own
  backend query — `sg_d3d11_query_image_info()` on your side, staging texture
  + `CopyResource`/`Map` polling). Keep the Metal path working (you can build
  the refactor blind for Metal; the macOS side re-validates). The async
  contract must hold: `readback_begin` never blocks the render loop,
  `readback_poll` returns 0/1/2, double print buffers, refuse a third dip
  with a WARN while both are unconsumed.
- **Clang-only flags**: `core/CMakeLists.txt` uses
  `-fvisibility=hidden -fno-exceptions -fno-rtti` unconditionally, and the
  top-level CMake enables OBJC/OBJCXX languages — both need `if(MSVC)` /
